# DJ-011 evidence report

## Outcome

Implemented and executed a real Playwright browser E2E workflow against the
local Docker Compose stack. It uses fictional seeded accounts and three
isolated Chromium contexts (customer, agent, administrator) on the fixed local
edge URL `http://127.0.0.1:8000`.

The browser test passed. It created and claimed a ticket, verified a real
browser-authenticated authorization rejection before the claim, exchanged live
WebSocket messages, reloaded/reconnected and recovered durable history,
started and cancelled an in-progress SSE response, requested a report, and
asserted completed output is rendered.

## Changes

- Added Playwright 1.64.1 project metadata and lockfile (`package.json`,
  `package-lock.json`) plus `playwright.config.js`.
- Added `tests/e2e/collabdesk.spec.js`, using independent browser contexts and
  uniquely prefixed fictional data for each run.
- Added an opt-in Compose value for `ASSISTANT_STREAM_TOKEN_DELAY_SECONDS`.
  The documented E2E command uses `0.15` seconds only so cancellation is
  observed while the stream is active; regular Compose defaults remain `0.005`.
- Added the `browser-e2e` GitHub Actions job. It runs the same Compose/seed/npm
  sequence, installs Chromium, and uploads the Playwright HTML report.
- Added reproducible local E2E commands to `README.md` and ignored generated
  Node/Playwright artifacts.

While the API was deliberately running with the E2E-only `0.15` second stream
delay, the existing 12-concurrent-stream timing test timed out. That setting
is intentionally much slower than the application default and is not used for
the normal suite. I restored the default Compose configuration and reran the
entire suite successfully as recorded above.

An attempted E2E-only assertion of the pre-claim WebSocket close label also
failed: because the server rejects that socket before accepting the handshake,
Chrome exposes a generic connection error rather than the server's `4403`
application close code. The final test therefore retains the direct,
browser-session REST assertion of the authoritative `403
participant_forbidden` response; the finalized E2E command passed afterward.

## Reproduction

```bash
ASSISTANT_STREAM_TOKEN_DELAY_SECONDS=0.15 docker compose up --build -d --wait --wait-timeout 120
docker compose exec -T api python manage.py seed_local_accounts --password local-demo-password
npm ci
npx playwright install chromium
E2E_BASE_URL=http://127.0.0.1:8000 npm run e2e
```

When using a locally installed Chrome rather than a Playwright-downloaded
browser, replace the last line with:

```bash
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/google-chrome E2E_BASE_URL=http://127.0.0.1:8000 npm run e2e
```

## Remaining gaps

- No cross-browser matrix, load test, or accessibility audit was run.
- The success screenshot and HTML report are intentionally generated artifacts
  under ignored Playwright output directories; they are not source-controlled.

## Security notes

- The test uses only the repository's local demo accounts and uniquely named
  fictional ticket/message text; no production system, private project,
  customer data, token, or secret was accessed.
- Browser authentication remains the existing same-origin session plus CSRF
  handling. The test does not request, store, or put bearer tokens in URLs.
- The authorization assertion proves an agent receives `403
  participant_forbidden` for an unclaimed ticket conversation before claiming.
- The SSE test uses the bounded deterministic local assistant; no external AI
  provider is contacted.
