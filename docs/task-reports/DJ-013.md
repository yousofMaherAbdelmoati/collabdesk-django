## Remaining gaps and limitations

- `pip-audit` reported these unresolved findings: five DRF 3.15.2 advisories
  (fixes start at 3.17.2/3.18.2), duplicated PYSEC-2026-1845 entries for pytest
  8.4.2 (fix 9.0.3), and six Twisted 26.4.0 CVEs (the audit lists 26.10.0rc1
  where available). The declared `<3.16` DRF and `<9` pytest constraints make
  the suggested upgrades scope-changing; they need compatibility review and
  full retesting before production use.
- No Git history could be scanned because the supplied workspace is not a Git
  repository. Scan history with a repository-aware scanner after cloning the
  intended repository.
- No remote GitHub Actions status, production deployment, cloud-service test,
  load test, accessibility audit, formal penetration test, cross-browser
  matrix, backup/restore test, or disaster-recovery exercise was performed.
- Existing benchmark links are retained as repository evidence. This task did
  not rerun the 10k/50k/100k benchmark; it did run the full suite that includes
  deterministic benchmark unit coverage. The benchmark is local Compose
  PostgreSQL plus `LocMemCache`, not a Redis or production-capacity result.

## Security notes

- `.env`, `.env.*`, local SQLite files, Playwright output, virtualenvs, and
  node modules are ignored; `.env.example` contains only illustrative local
  settings.
- `seed_local_accounts` and the benchmark seeder are explicitly local/dev/test
  guarded and use fictional accounts/data; no real customer data, production
  service, private repository, or secret was accessed.
- README threat notes cover explicit CORS/CSRF origins, HttpOnly/SameSite
  sessions, secure cookies outside debug, hashed short-lived bearer tokens,
  authorization boundaries, idempotent retries, Redis degradation, and
  at-least-once worker delivery. They also state the outstanding operational
  requirements and the unresolved advisory risk.
