# DJ-008 — Django analytics and report downloads

Date: 2026-10-24

## Result

PASS — analytics/report behavior and its PostgreSQL-backed job tests were
implemented and verified with fictional fixed fixtures.

## Changes

- Replaced the report's raw `.extra()` date SQL with `TruncDate` and
  `TruncMonth` in UTC. Reports now accept canonical `start`, `end`,
  `statuses`, `agent_id`, and `granularity` filters; JSON-compatible legacy or
  extension parameters remain part of the request fingerprint without altering
  built-in filtering.
- Defined first response as the first post-creation message from the assigned
  agent. Bucket and per-agent metrics include response counts/average seconds,
  assigned tickets, and resolved tickets. Output order and bucket timezone are
  fixed for reproducible aggregation.
- Added `AnalyticsSummary` daily/monthly materialized buckets and migration
  `reports.0003`. A report worker commits result output, expiry metadata, and
  summary updates in one database transaction before writing the optional Redis
  cache. Each materialized bucket has its own agent activity values.
  Ticket/message commits invalidate affected materializations; scheduled refresh
  rebuilds recent UTC buckets.
- Added result TTL/expiry configuration, periodic expiry and refresh tasks,
  cache deletion on expiry, and `refresh: true` policy for a deliberate new
  report run. Expired results (including completed legacy rows without expiry
  metadata) return HTTP 410 and cannot be reused.
- Added admin-only cursor-paginated report-job listing and ready-result JSON or
  CSV download at `GET /api/reports/{id}/download?format=json|csv`.
- Added fixed-fixture tests for metrics/query correctness, summary persistence
  and invalidation, authorization, pagination/filtering, JSON/CSV output,
  expiry/cache invalidation, refresh policy, durable cache ordering, retries,
  duplicate delivery, and PostgreSQL concurrent request/worker claims.

## Security notes

- Every report list, detail, and download endpoint checks the administrator
  role before exposing job metadata or output. CSV contains aggregate numeric
  data and numeric agent IDs only, not ticket text or user names.
- PostgreSQL remains authoritative: the database transaction persists report
  result/expiry/materializations before the best-effort Redis cache write.
  Cache expiry failure cannot make an expired result downloadable because the
  database expiry check is performed first.
- UTC aggregation, bounded result retention, summary invalidation after source
  changes, lease-token completion, and generic worker errors reduce stale-data,
  race, and data-leak exposure. Celery delivery remains intentionally
  at-least-once rather than exactly-once.
