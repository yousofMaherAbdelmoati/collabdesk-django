# DJ-010 evidence report

## Outcome

Implemented the authenticated CollabDesk browser demonstration and verified the
application, Compose stack, API/Channels/SSE/report integration tests, and
served UI shell. The demo is available at:

- http://localhost:8000/ — authenticated customer, agent, and administrator local demo
- http://localhost:8000/api/docs/ — API documentation

## Changes

- Added the root Django-rendered demo route in config/urls.py and the
  intentionally small apps.desk.frontend.demo_ui view.
- Configured Django templates to load the existing frontend/ directory.
- Added the explicit local Compose origins (localhost/127.0.0.1 port 8000) to
  the CSRF, CORS, and WebSocket allow-lists. This is required because the demo
  is now served by Django itself rather than by the old port-3000 client.
- Replaced the placeholder HTML with a responsive, same-origin authenticated
  client that provides session/CSRF login/logout, customer ticket creation
  with generated idempotency keys, customer/agent/admin ticket workspaces,
  agent claims, and clear retry/error states.
- Added Django Channels conversation support in the client: WebSocket live
  messages, automatic reconnect, history sync after the last durable id, and
  read acknowledgements.
- Added deterministic assistant SSE start/cancel UI plus administrator cache
  display, asynchronous report request/poll/retry/result display, and
  development/test-only idempotency and claim-race controls.
- The local controls are template-gated by LOCAL_DEMO_SEED_ENABLED and only
  call existing authenticated API endpoints. No privileged test endpoint was
  created.
- Added tests/test_demo_ui.py for the root UI shell and production-like
  omission of the local test panel.
- Documented Compose startup, URLs, fictional accounts, two-browser
  walkthrough, and local-test-panel safety in README.md.

## Security notes

- The UI uses same-origin session authentication and CSRF headers; it neither
  requests nor persists browser bearer tokens.
- WebSocket URLs contain only ticket identifiers; authentication remains the
  existing HttpOnly session cookie and server-side participant authorization.
- The assistant explicitly uses the existing bounded deterministic local
  provider; no external AI or customer data connection is added.
- Local test controls are omitted outside local/test environments and use only
  normal role-protected endpoints. The existing seed command remains
  development/test-only and requires an explicit password.
