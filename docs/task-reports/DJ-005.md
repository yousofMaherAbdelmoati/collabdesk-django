# DJ-005 — Harden Django asynchronous SSE streaming

## Result

PASS. The assistant SSE endpoint now streams from a local deterministic async
provider. No external AI service, private project, production system, secret,
or customer data was accessed.

## Changes

- Added `apps.desk.streaming` with an async provider protocol and a deterministic
  local provider. It uses `asyncio.sleep`, never `time.sleep`.
- Replaced the synchronous response generator with an async iterator passed to
  Django's `StreamingHttpResponse`; this is consumed natively by the existing
  ASGI application.
- Added JSON SSE framing (`event` plus `data`, UTF-8, blank-line terminated),
  an overall stream timeout, 32-chunk/4096-character configurable limits, and
  `token`, `complete`, and `error` terminal events.
- Added cooperative close/cancellation handling and process-local aggregate
  counters for starts, active/max-active, completion, errors, timeouts,
  disconnects, and limits.
- Added outcome-only operational logging. Prompt text, streamed text, ticket
  ids, user ids, and provider exception detail are not logged.
- Added tests for frame validity, token ordering, completion, error, timeout,
  character/chunk bounds, provider cleanup on disconnect, bounded shutdown,
  12 concurrent abstraction-level streams, and 12 concurrent authenticated
  requests through Django's ASGI application.

## Remaining gaps

- Validation used Django's in-process ASGI test harness and local SQLite test
  configuration. PostgreSQL, Redis, Docker, browser, external-provider, and
  load-test validation were not executed or claimed; this task changes no
  database or Redis behavior.
- The counters are process-local by design. A multi-process deployment should
  export the aggregate values through its existing metrics collector.

## Security notes

- The provider is deterministic and local; no paid AI API or network call is
  made.
- Output is bounded by both chunk count and character count; timeout and
  disconnect paths release provider resources.
- Logs intentionally contain only fixed event names and outcomes. They do not
  contain prompts, token output, IDs, or provider error text.
