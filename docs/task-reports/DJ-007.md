# DJ-007 — Harden Celery report jobs and outbox publisher

Date: 2026-10-24

## Result

PASS — the report job handoff is now transactionally outboxed, report and
publisher work are lease-protected, and the targeted SQLite and PostgreSQL
tests passed.

## Changes

- Added `ReportJob` lease token, expiry, heartbeat, next-attempt timestamp,
  scheduling index, and a PostgreSQL/SQLite-supported partial unique
  constraint for active equivalent report fingerprints.
- Added outbox state, availability, lease, bounded-attempt, terminal-failure,
  and diagnostic fields plus an indexed publisher scan. The migration preserves
  any pre-existing non-null `published_at` rows as `published`.
- Changed report requests to commit the job and `report.run` event together.
  The post-commit Celery wake-up is best effort only; periodic beat publishing
  is the recovery path.
- Added a leased outbox publisher, lease/heartbeat report runner, stale-job
  watchdog, bounded exponential retry scheduling, and terminal policies.
  Completion conditionally persists the database result before attempting the
  optional Redis cache write.
- Configured Celery beat schedules and the local worker's beat process for
  publisher/watchdog recovery.
- Added failure-mode tests covering durable handoff during a simulated
  Redis/Celery wake failure, Celery publish failure, publisher restart,
  duplicate task delivery, cache ordering, retries/terminal failure,
  watchdog recovery, heartbeats, and competing PostgreSQL requests/workers.
- Documented the explicit at-least-once (not exactly-once) boundary in the
  README and architecture notes.

## Remaining verification boundaries

- The outage tests inject failures at the Celery publish/wake API boundary;
  they verify that PostgreSQL preserves the event and retry state. A live
  Redis shutdown or a separately restarted worker process was not performed,
  and is not claimed here.
- Browser, load, production deployment, external services, and real customer
  data were not used.

## Security notes

- PostgreSQL is the source of truth. Redis/Celery is a transport/cache only;
  broker failure cannot roll back a committed report job or outbox event.
- Lease tokens prevent a stale worker from persisting over a newer owner.
  Duplicate publishes/deliveries remain possible after a crash at the broker
  acknowledgement boundary, so the implementation makes persisted result
  completion idempotent and makes no exactly-once assertion.
- API-visible report and persisted outbox errors are generic; raw broker or
  database exception messages are not stored in those records.
